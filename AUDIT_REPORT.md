3. Honeypot отвечает тихо и **до** rate-limit/валидации — боты не сжирают лимит и не получают деталей ошибок.
4. Полная серверная валидация, дублирующая клиент: согласие обязательно (400 без него), allowlist способов связи, строгий ник `[A-Za-z0-9_]{4,}`, телефон 10–15 цифр, длина имени ≤120.
5. Пользовательский ввод не возвращается в JSON-ответ — reflected XSS через сообщения об ошибках закрыт структурно.
6. Во всём клиентском коде вывод только через `textContent` / `createTextNode`; `innerHTML` / `insertAdjacentHTML` / `document.write` / `eval` отсутствуют (grep — 0 совпадений).
7. Rate-limit 5/60 с JSON-хранилищем есть, покрыт тестами (6-я заявка → 429), защищён `flock` на всём цикле, мёртвые IP вычищаются.
8. Политика 152-ФЗ: `noindex`, чекбокс без pre-checked, ссылка в новой вкладке, текст про РФ без трансграничной передачи; ротация ПДн-лога — `scripts/prune-logs.php`.
9. Ноль внешних CDN/аналитик: локальные woff2, `package.json` без `dependencies` — минимальная supply-chain атака.
10. Сборка статики изолирована: в `site/` не уезжают `send.php`, `config/`, `logs/`, `tests` (страховка в `scripts/build.js` + `.gitignore`).
11. Мобильная база по ТЗ: база 16px, поля 16px (iOS без авто-зума), кнопки 54px, липкая CTA с `env(safe-area-inset-bottom)`, `prefers-reduced-motion`, без `user-scalable=no`.
12. Автотесты формы реальные (через `php -S`), 26/26 PASS, включая honeypot, согласие и rate-limit; `node --check` и `php -l` чистые; CI подключён.
