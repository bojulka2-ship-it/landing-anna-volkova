# Лендинг «Анна Волкова — репетитор английского языка»

Продающая одностраничная форма для частного репетитора: Москва (офлайн) и онлайн.  
Статический сайт + PHP-форма заявок, согласие на обработку персональных данных (152-ФЗ), демо-режим на GitHub Pages.

**Демо (интерфейс, заявки не уходят):** https://bojulka2-ship-it.github.io/landing-anna-volkova/

Этот README — инструкция для человека, который **впервые** открыл репозиторий: что это, как запустить у себя, как настроить, как выложить на боевой домен в России.

> **Про команды:** примеры рассчитаны на **bash / cmd / Git Bash** (в CI и на хостингах).  
> В **Windows PowerShell 5.1** символ `&&` не работает — запускайте команды **по одной** или откройте Git Bash.

---

## Назначение и возможности

**Зачем проект**

- Собирать заявки на пробное занятие (500 ₽) с лендинга.
- Показывать интерфейс заказчику без реальной отправки (демо).
- Работать на хостинге в РФ: данные заявок не покидают Российскую Федерацию.

**Что умеет**

| Возможность | Как |
|-------------|-----|
| Форма заявки | Имя, телефон с маской, способ связи, ник в мессенджере, согласие на ПДн |
| Валидация | На клиенте и на сервере; ошибки на русском |
| Защита от спама | Honeypot, rate-limit (5 заявок / 60 сек с IP), только JSON, лимит тела 64 КБ |
| Письма | Режим `test` — пишет в лог без письма; `real` — письмо менеджеру через PHP `mail()` |
| 152-ФЗ | Страница политики, явное согласие, `noindex`, логи с правами `0600`, ротация ПДн |
| Демо на GitHub Pages | Авто-детект `*.github.io`: форма «принимает», но ничего не отправляет |
| Автотесты | 27 PHP-проверок формы + 15 JS unit-тестов + CI на GitHub |
| Сборка для деплоя | `site/` — чистая статика без PHP, конфигов и логов |

## Интерфейс

Секции сверху вниз:

1. **Первый экран** — H1, оффер «Пробное 500 ₽», кнопка записи, телефон.
2. **Боли клиента** — 3 ситуации.
3. **Решения** — системный подход, 3 пункта.
4. **Обо мне** — фото, кейсы, сертификаты (CELTA/TKT).
5. **Форматы и цены** — 4 позиции, пробное 500 ₽, далее от 1 000 ₽.
6. **Оффер** — возврат 500 ₽, акция «абонемент −15%», 3 слота.
7. **Отзывы** — 2 скриншота (сейчас демо-заглушки, заменяются на реальные).
8. **Форма заявки** — поля + чекбокс согласия.
9. **Футер** — политика 152-ФЗ, телефон; в demo — бейдж и ссылка на пример письма.

На мобильном — липкая нижняя панель «Позвонить / Оставить заявку».

## Системные требования

**Для локального запуска и разработки**

| Компонент | Версия | Обязателен? |
|-----------|--------|-------------|
| PHP | 8.0+ | да — форма и тесты |
| Node.js | 18+ | для тестов, сборки, сканов (сайт без Node тоже открывается) |
| Git | любой | для клонирования |
| Браузер | современный (Chrome/Firefox/Safari/Edge) | да |

**Для боевого хостинга**

- PHP 8.0+ (8.2 рекомендуется);
- Apache с `mod_rewrite`/`.htaccess` **или** nginx (блоки `deny` — в разделе деплоя);
- доступ к настройке почты для SPF/DKIM (когда включается `real`).

**Чего не нужно**

- Базы данных — заявки идут в письмо и/или текстовый лог.
- Python и виртуальное окружение в привычном смысле (см. ниже).
- Внешних CDN, платных API, сторонних трекеров.

## Установка с чистого компьютера

Команды копируются целиком.

### 1. Клонирование

```bash
git clone https://github.com/bojulka2-ship-it/landing-anna-volkova.git
cd landing-anna-volkova
```

### 2. Проверка, что PHP и Node на месте

```bash
php -v
node -v
```

Нужно: PHP ≥ 8.0, Node ≥ 18.  
Если PHP нет — установите с [php.net/windows](https://www.php.net/downloads.php) или через пакетный менеджер ОС и убедитесь, что `php` доступен в терминале.

### 3. Виртуальное окружение

**Виртуальное окружение в проекте не требуется.**

- В `package.json` **ноль** npm-зависимостей — `npm install` ничего не ставит (папка `node_modules` не нужна для запуска и тестов).
- PHP используется системный (или portable) — отдельный venv, как в Python, здесь не применяется.

Опционально, если хотите изолировать PHP от системного:

```bash
# пример: отдельный каталог portable-PHP и запуск из него
mkdir -p "$HOME/php-portable"
# распакуйте туда дистрибутив PHP и запускайте сервер полным путём к php.exe / php
```

Для боевого хостинга виртуальное окружение создавать не нужно: хостинг уже даёт PHP.

### 4. Локальный запуск

```bash
php -S 127.0.0.1:8080
```

Откройте в браузере:

```text
http://127.0.0.1:8080/
```

По умолчанию `MAIL_MODE=test`: заявки пишутся в `logs/submissions.log`, письма **не** уходят.

Остановить сервер: `Ctrl+C` в том же терминале.

## Конфигурация

### PHP (`send.php` + `config/`)

| Файл | Роль |
|------|------|
| `config/managers.php` | шаблон, плейсхолдеры, лежит в git |
| `config/managers.local.php` | рабочие значения, **только локально / на хостинге**, в `.gitignore` |

Приоритет: **переменные окружения** > `managers.local.php` > `managers.php`.

Копия для локальной настройки:

```bash
cp config/managers.php config/managers.local.php
```

Далее откройте `config/managers.local.php` в редакторе и заполните **свои** значения. Файл не коммитится.

Режимы `MAIL_MODE`:

- `test` — запись в лог, письмо не шлётся (по умолчанию, для настройки);
- `real` — письмо через PHP `mail()` на адрес из конфига.

### Переменные окружения (только имена)

Если хостинг или CI задаёт env, эти имена имеют приоритет над файлами:

| Имя переменной | Назначение |
|----------------|------------|
| `MAIL_MODE` | режим отправки письма |
| `TO_EMAIL` | куда приходят заявки |
| `FROM_EMAIL` | адрес отправителя |
| `SUBJECT` | тема письма |
| `SITENAME` | название сайта в письмах/логах |

Значения в README не хранятся — подставляйте только на хостинге или в личном `managers.local.php`.

### Бэкенд на стороне клиента (`js/config.js`)

```js
var API_URL = "/send.php";      // PHP-хостинг (основной)
// var API_URL = "/api/submit"; // опциональный Node-бэкенд
```

Автоматически: если хост заканчивается на `.github.io`, включается **демо-режим** — форма не отправляет данные.

Опциональный Node-бэкенд: смените `API_URL` на свой эндпоинт и разверните его отдельно; PHP-часть при этом не обязательна.

## Где хранятся заявки и как их чистить

Заявки накапливаются **по-разному** в зависимости от `MAIL_MODE`. На демо (`*.github.io`) они не сохраняются нигде.

### Режим `test` (по умолчанию)

- Каждая заявка **дописывается** в текстовый файл `logs/submissions.log`.
- Одна строка (JSON) на заявку: имя, телефон, способ связи, ник, согласие, IP, время.
- Файл создаётся автоматически; права после записи — `0600`.
- Письма **не** уходят.
- Файл живёт только на сервере / у вас локально — **в git и на GitHub Pages не попадает**.

### Режим `real`

- Заявка уходит **письмом** на `TO_EMAIL` через PHP `mail()`.
- Запись также добавляется в `logs/submissions.log` (как след).
- Основное «хранилище» на боевом контуре — **почтовый ящик менеджера**.

### Чистка лога (ротация ПДн)

**1. Автоматически (рекомендуется)** — скрипт ротации:

```bash
php scripts/prune-logs.php
php scripts/prune-logs.php 90
```

- Без аргумента и с `90` — удаляет записи **старше 90 дней**.
- Аргумент — возраст в днях.
- Заодно чистит `logs/rate-limit.json`.

На хостинге можно повесить на cron (раз в сутки), например:

```bash
0 4 * * * /usr/bin/php /путь/к/сайту/scripts/prune-logs.php 90
```

Путь к `php` уточните в панели вашего хостинга.

**2. Вручную — очистить всё:**

```bash
: > logs/submissions.log
```

В Windows (PowerShell):

```powershell
Clear-Content logs\submissions.log
```

**3. Удалить файл совсем** (создастся заново при следующей заявке):

```bash
rm logs/submissions.log
```

**4. Перед сдачей / если в логе остались тестовые заявки:**

```bash
php scripts/prune-logs.php 0
```

или проще — очистить файл вручную (команда выше).

**Коротко:** копятся в `logs/submissions.log` (режим `test`) и в почте (`real`); чистятся `php scripts/prune-logs.php 90` или вручную; на demo-странице GitHub Pages — не копятся.

## Проверка работоспособности

Из корня проекта (все команды копируемые):

```bash
# 1. Синтаксис JS
node --check js/core.js && node --check js/script.js && node --check js/config.js

# 2. JS unit-тесты (маска, валидация, resetForm)

php -l send.php && php -l scripts/prune-logs.php && php -l tests/run_tests.php

# 4. Автотесты формы (ожидается PASS=27, FAIL=0)
php tests/run_tests.php

# 5. Всё сразу
npm test

# 6. Сборка site/ + скан «нет ПДн в публикуемом»
npm run scan:pii
```

**Ручная smoke-проверка после `php -S 127.0.0.1:8080`:**

1. Открыть `http://127.0.0.1:8080/` — все секции на месте.
2. Ввести в телефон `89991234567` → должно стать `+7 (999) 123-45-67`.
3. Выбрать Telegram → появилось поле ника; «Перезвонить» → поле скрылось.
4. Отправить без чекбокса согласия → ошибка на русском.
5. Отправить валидную заявку → «Спасибо!…»; появилась строка в `logs/submissions.log`.

## Демо-режим и публикация (GitHub Pages)

Демо = публикация папки `site/` на GitHub Pages. Заявки **не** сохраняются и **не** отправляются.

**Как это уже настроено в репозитории**

1. Push в ветку `master` запускает `.github/workflows/pages.yml`.
2. CI собирает `site/` (`node scripts/build.js`).
3. Скан `node scripts/scan_site_pii.js` — публикация падает, если в `site/` найдены логи, почта конфига, ключи и т.п.
4. Артефакт `site/` выкладывается на Pages.

**Если переносите репозиторий на другой аккаунт**

```bash
git remote set-url origin https://github.com/USER/REPO.git
git push -u origin master
```

В настройках репозитория: **Settings → Pages → Source = GitHub Actions**.

Локальная проверка перед пушем:

```bash
npm run scan:pii
```

### Чек-лист: как работает демо и что проверить

1. Открыть главную: все секции, телефон-заглушка `+7 (900) 000-00-00`.
2. Ширина 320 и 375 px: нет горизонтального скролла, кнопки ≥52 px, текст ≥16 px.
3. Липкая панель «Позвонить / Оставить заявку» видна при скролле (моб.).
4. Маска: ввод `89991234567` → `+7 (999) 123-45-67`.
5. Смена способа связи: у мессенджеров видно поле ника, у «Перезвонить» — нет.
6. Отправка без согласия → ошибка на русском, заявка не уходит.
7. Успешная отправка в demo → сообщение с меткой «демо-режим» и ссылкой на `zayavka.html`.
8. В футере — ссылка «Пример письма менеджеру» и бейдж «Демо-режим».
9. `policy.html` открывается в новой вкладке, содержит текст 152-ФЗ.
10. **Демо НЕ принимает заявки** — предупредить заказчика: это витрина интерфейса.
11. `https://…github.io/…/logs/submissions.log` и `…/config/managers.php` → **404** (файлов нет в публикации).
12. Демо-ссылка: https://bojulka2-ship-it.github.io/landing-anna-volkova/

Локально реальную отправку (в режиме test) проверяйте через `php -S 127.0.0.1:8080` и `logs/submissions.log`.

## Запуск на реальном домене в России после покупки заказчиком

Основной сценарий — **российский регистратор + хостинг с PHP в РФ**. Иностранные хостинги как основные не используются (данные заявок должны оставаться в РФ). GitHub Pages — только для бесплатного демо интерфейса.

### Пошагово

**1. Домен**  
Купить у регистратора РФ: REG.RU, RU-CENTER, Names.ru и аналоги.

**2. Хостинг с PHP в РФ**  
REG.RU, Beget, Timeweb, Sprinthost и другие хостинги с PHP 8.x. Данные заявок не покидают РФ — требование 152-ФЗ по локации хранения выполняется.

**3. Загрузка файлов**

В корень сайта (`public_html` / `www` / `htdocs`):

- содержимое папки `site/` (собрать локально: `npm run build`);
- **плюс** `send.php`;
- **плюс** папки `config/` и `logs/` (в `site/` их нет — на сервере они нужны).

Или залить весь корень репозитория, но тогда обязательно закрыть от веба `config/`, `logs/`, `tests/`, `scripts/` (см. шаг 6).

Сборка и защита локально перед заливкой:

```bash
npm run scan:pii
```

**4. Конфигурация**

- Скопировать на сервер `config/managers.local.php` и заполнить **свои** значения (или задать env: `MAIL_MODE`, `TO_EMAIL`, `FROM_EMAIL`, `SUBJECT`, `SITENAME`).
- Первый заход: `MAIL_MODE` в режиме теста (`test`).

**5. Телефон и реквизиты**

- Заменить `+7 (900) 000-00-00` на реальный номер (в `index.html` — 4 места; при необходимости в футерах `policy.html` / `zayavka.html`).
- В `policy.html` заполнить реквизиты оператора: ФИО, ИНН, ОГРНИП, адрес, e-mail вместо плейсхолдеров.
- При необходимости заменить демо-отзывы в `images/` на реальные скриншоты.

**6. Проверка 403 на служебные пути**

В браузере открыть:

```text
https://ВАШ-ДОМЕН/config/managers.local.php
https://ВАШ-ДОМЕН/logs/submissions.log
https://ВАШ-ДОМЕН/tests/run_tests.php
https://ВАШ-ДОМЕН/scripts/build.js
```

Ожидание: **403** (или 404).  
На Apache это дают `.htaccess` в `config/`, `logs/` и корневой `.htaccess`.  
На **nginx** в конфиг сайта добавьте (значения домена не нужны — только блоки):

```nginx
location ^~ /config/  { deny all; }
location ^~ /logs/    { deny all; }
location ^~ /tests/   { deny all; }
location ^~ /scripts/ { deny all; }
```

Те же security-заголовки, что в корневом `.htaccess` проекта (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, CSP).

**7. Тестовое письмо**

1. Режим `test`: отправить заявку → строка в `logs/submissions.log`.
2. Переключить `MAIL_MODE` на `real` → отправить ещё одну → письмо приходит на `TO_EMAIL`.

**8. SPF/DKIM**

Настроить на ящике `FROM_EMAIL` (документация регистратора/хостинга), иначе письма уходят в спам.

**9. Передача заказчику**

- доступы: хостинг, домен, почта менеджера, репозиторий;
- этот `README.md` и `ACCEPTANCE_CHECKLIST.md`;
- напомнить: демо на github.io заявки не принимает; боевой приём — только на домене с PHP.

## Резервное копирование

Копировать регулярно (раз в неделю или перед каждым обновлением):

| Что | Зачем |
|-----|--------|
| `config/managers.local.php` | секреты и режим письма |
| `logs/submissions.log` | история заявок в режиме `test` / fallback |
| Каталог сайта (весь `public_html`) | быстрый откат |
| База не нужна | БД в проекте нет |

Как заявки копятся и как чистить лог — раздел **[Где хранятся заявки и как их чистить](#где-хранятся-заявки-и-как-их-чистить)**.

Пример архива на сервере (запускать в корне сайта):

```bash
tar -czf backup-site-$(date +%F).tar.gz send.php config logs index.html policy.html zayavka.html css js fonts images .htaccess
```

Локально (копия репозитория + секреты):

```bash
git clone https://github.com/bojulka2-ship-it/landing-anna-volkova.git backup-landing-$(date +%F)
```

`managers.local.php` в git не входит — храните его отдельно в безопасном месте (менеджер паролей, зашифрованный архив).

Очистка ПДн-лога (ротация, по умолчанию 90 дней):

```bash
php scripts/prune-logs.php
php scripts/prune-logs.php 90
```

На хостинге можно повесить на cron.

## Если что-то не работает

| Симптом | Что проверить |
|---------|----------------|
| `php: command not found` | Установите PHP 8+ и добавьте в PATH; проверьте `php -v` |
| `node: command not found` | Установите Node 18+; проверьте `node -v` |
| Белая страница / 500 на `send.php` | `php -l send.php`; права на запись в `logs/`; смотрите лог ошибок хостинга |
| Форма отвечает, но письма нет | Сначала `MAIL_MODE=test` (смотрите `logs/submissions.log`); для `real` — адреса в `managers.local.php` или env, SPF/DKIM |
| `415` при отправке | Клиент должен слать `Content-Type: application/json` (так и делает штатный `js/script.js`) |
| `413` | Тело запроса больше 64 КБ — это защита, не ошибка настройки |
| `429` | Rate-limit 5 заявок с IP за 60 сек — подождите минуту или очистите `logs/rate-limit.json` |
| Заявок много, лог растёт | `php scripts/prune-logs.php 90` или очистка вручную — см. раздел «Где хранятся заявки и как их чистить» |
| `400` «согласие» | Не отмечен чекбокс обработки ПДн — обязательно на клиенте и сервере |
| Нет поля ника | Выбран «Перезвонить» — поле скрыто намеренно; для мессенджеров оно появляется |
| Горизонтальный скролл на телефоне | Проверьте 320/375; в CSS оставлено `overflow-x: hidden` (осознанное ограничение) |
| Демо «принимает», но заявка не приходит | Норма: на `*.github.io` включён демо-режим, данные не отправляются |
| `logs/` или `config/` открываются в браузере | Срочно: на nginx добавьте `deny all`, на Apache — `.htaccess`; после этого снова откройте URL — должен быть 403 |
| Тесты PHP не стартуют | `php` должен быть в PATH; порт 8976 не занят |
| `npm install` «ничего не поставил» | Это нормально: зависимостей нет |
| Скрипты скриншотов падают | Нужен Chrome и `npm install --no-save puppeteer-core` (только для разработки, не для боевого сайта) |
| CI красный на GitHub | Откройте вкладку Actions → лог упавшего шага; локально повторите `npm test` |

Куда смотреть дальше: `ACCEPTANCE_CHECKLIST.md` (приёмка), `AUDIT_REPORT.md` (аудит).

## Известные ограничения

1. **Телефон-заглушка** `+7 (900) 000-00-00` — заменяется заказчиком на реальный номер.
2. **Реквизиты в `policy.html`** — плейсхолдеры до данных оператора (ФИО, ИНН, ОГРНИП, адрес, e-mail).
3. **Отзывы** — временные демо-картинки; ставятся реальные скриншоты из переписки.
4. **`MAIL_MODE` по умолчанию `test`** — письма не уходят, пока не включат `real` и не настроят SPF/DKIM.
5. **E-mail в форме не собирается** — осознанно (контакт: телефон/месенджеры).
6. **Демо на GitHub Pages не принимает заявки** — только витрина интерфейса.
7. **Rate-limit и honeypot** — эвристики; продвинутый бот с ротацией IP может обойти (полная защита — WAF/капча при необходимости).
8. **`overflow-x: hidden`** оставлен по решению заказчика (боковой скролл запрещён).
9. **Общего reverse-proxy нет** — лимит по `REMOTE_ADDR`; XFF не внедрялся.
10. **`.htaccess`** проверяется на живом Apache/nginx уже на хостинге (приёмка `403` — после деплоя).
11. **Node-бэкенд (`/api/submit`)** — только опция в `config.js`, основной путь — PHP `send.php`.
12. **Скриншоты/браузерные скрипты** — для разработки; на боевом сервере не нужны.

## Сильные стороны проекта

1. **Готов к передаче:** README, чек-лист приёмки, отчёт аудита — в репозитории.
2. **Данные в РФ:** основной контур — PHP-хостинг в России; 152-ФЗ (политика, согласие, noindex, ротация логов).
3. **Безопасность по умолчанию:** JSON-only, лимиты тела и rate-limit, honeypot, `chmod 0600` на логи, запрет веб-доступа к `config/` и `logs/`, CSP и anti-clickjacking.
4. **Секреты вне git:** `managers.local.php` и логи в `.gitignore`; env-переменные с приоритетом над файлами.
5. **Ноль внешних зависимостей на проде:** нет CDN, нет npm-зависимостей, локальные шрифты — минимальная supply-chain атака.
6. **Автотесты и CI:** 27 PHP + 15 JS unit, синтаксис, сборка, PII-скан на каждом push; deploy Pages с тем же сканом.
7. **Демо без риска:** github.io показывает UI и не трогает ПДн; публикация физически не содержит логов и конфига.
8. **Двойная валидация:** клиент и сервер говорят по-русски и не расходятся по правилам.
9. **Доступность:** маска телефона, условные поля, `aria-live`, видимый фокус, `prefers-reduced-motion`, адаптив 320–1440.
10. **Простая эксплуатация:** без БД, текстовый лог + письмо, понятные команды `npm test` / `npm run build`, ротация ПДн одной командой.
11. **Честный деплой:** основной боевой путь — российский хостинг; зарубежный Pages — только демо, оговорено в документации.
12. **Проверено:** аудит, ручная приёмка формы, скриншоты брейкпоинтов, зелёный CI на GitHub.
