# Лендинг «Анна Волкова — репетитор английского языка»

Продающая одностраничная форма для частного репетитора английского языка (Москва, офлайн + онлайн). Статический сайт + PHP-бэкенд формы заявок, 152-ФЗ, demo-режим для GitHub Pages.

## Назначение

- Собрать заявки на пробное занятие (500 ₽) с лендинга.
- Работать на хостингах в РФ (PHP): данные не покидают Российскую Федерацию.
- Демонстрировать заказчику интерфейс на GitHub Pages без реальной отправки.

## Интерфейс (секции сверху вниз)

1. Первый экран: H1, оффер «Пробное 500 ₽», CTA, телефон.
2. Боли клиента (3 карточки).
3. Решения / системный подход (3 карточки).
4. Обо мне: фото, кейсы, сертификаты.
5. Форматы и цены: 4 позиции, пробное 500 ₽, далее от 1 000 ₽.
6. Оффер: возврат 500 ₽, акция «абонемент на 10 занятий −15%», 3 слота.
7. Отзывы: 2 реальных скриншота из переписки (review-1, review-2).
8. Форма заявки: имя, телефон (маска), способ связи, условный ник, чекбокс согласия.
9. Футер: политика 152-ФЗ, телефон, демо-ссылка (только в demo).

На мобильном — липкая нижняя панель «Позвонить / Оставить заявку».

## Структура проекта

```
index.html              — лендинг + форма
policy.html             — политика обработки ПДн (152-ФЗ, noindex)
zayavka.html            — пример письма менеджеру (демо, noindex)
css/style.css           — Mobile-First, все токены темы в :root
js/config.js            — точка смены бэкенда (API_URL) + авто-детект github.io
js/script.js            — маска телефона, условные поля, согласие, отправка
send.php                — PHP-бэкенд формы
config/managers.php     — шаблон конфига (плейсхолдеры, в git)
config/managers.local.php — локальный конфиг (в .gitignore, секретов в git нет)
config/.htaccess        — запрет веб-доступа к конфигу
logs/                   — журнал test-режима + rate-limit (+ .htaccess)
scripts/build.js        — сборка чистой статики в site/
fonts/                  — локальные woff2 (Manrope + Inter, кириллица+latin) и fonts.css
images/                 — изображения (webp)

site/                   — собранная статика для деплоя (генерируется)
README.md               — этот файл
ACCEPTANCE_CHECKLIST.md — чек-лист приёмки заказчиком
```

## Локальный запуск

```bash
php -S 127.0.0.1:8080
```

Открыть http://127.0.0.1:8080/. Режим письма по умолчанию `test` — заявки пишутся в `logs/submissions.log`, письма не уходят.

Проверка:

```bash
node --check js/core.js && node --check js/script.js && node --check js/config.js
node --test tests/js_core.test.js   # JS unit (маска, валидация, resetForm)
php -l send.php && php -l scripts/prune-logs.php
php tests/run_tests.php      # ожидается 100% PASS
npm test                     # check + JS unit + PHP
node scripts/build.js        # сборка site/
npm run build                # то же самое
php scripts/prune-logs.php   # опционально: очистка ПДн-лога старше 90 дней
```

## Конфигурация

### Бэкенд (js/config.js)

```js
var API_URL = "/send.php";      // PHP-хостинг (основной)
// var API_URL = "/api/submit"; // опциональный Node-бэкенд
```

Автоматически: если хост `*.github.io`, `IS_GITHUB_PAGES = true` → форма **имитирует** приём («демо-режим»), ничего не отправляет, в футере и в сообщении успеха появляется ссылка на `zayavka.html`.

### PHP-конфиг (config/)

| Файл | Назначение |
|------|------------|
| `managers.php` | шаблон с плейсхолдерами, лежит в git |
| `managers.local.php` | реальные значения, **в .gitignore**, секреты только здесь |

Ключи: `MAIL_MODE` (`test`/`real`), `TO_EMAIL`, `FROM_EMAIL`, `SUBJECT`, `SITENAME`.

- `test` — заявка пишется в `logs/submissions.log`, письмо не шлётся (режим настройки, по умолчанию).
- `real` — письмо уходит через PHP `mail()` на `TO_EMAIL`.

### Защита формы

- Имя ≤120 символов (без управляющих символов); телефон 10–15 цифр; ник `[A-Za-z0-9_]{4,}` (для мессенджеров); e-mail-валидация не используется — поле e-mail исключено из формы по решению заказчика.
- Согласие на ПДн обязательно: клиент блокирует отправку, сервер отвечает 400.
- Honeypot: скрытое поле `company`; если заполнено — тихий `ok`, письмо не шлётся.
- Rate-limit: ≤5 заявок с одного IP за 60 сек, иначе 429; файл `logs/rate-limit.json` с `flock`, права `0600`.
- Приём только JSON (`Content-Type: application/json`); form-urlencoded → 415; тело >64 КБ → 413.
- Логи `logs/submissions.log` / `rate-limit.json` — права `0600` после записи; очистка: `php scripts/prune-logs.php 90`.

### Безопасность (аудит)

- Заголовки (Apache, корневой `.htaccess`): `nosniff`, `X-Frame-Options`, `Referrer-Policy`, CSP `default-src 'self'` …; на **nginx** задать те же header + `location ^~ /config/ { deny all; }` и `location ^~ /logs/ { deny all; }` (плюс `tests/`, `scripts/`).
- Секреты: приоритет **env** (`TO_EMAIL`, `FROM_EMAIL`, `MAIL_MODE`, …) > `config/managers.local.php` > шаблон `managers.php`.
- ПДн-лог: `php scripts/prune-logs.php [дни]` (по умолчанию 90 дней) — cron/задание на хостинге.
- CI: `.github/workflows/ci.yml` — `node --check`, JS unit (`node --test`), `php -l`, `php tests/run_tests.php`, `node scripts/build.js` на каждый push/PR.

### 152-ФЗ

- `policy.html` — оператор (реквизиты-плейсхолдеры), состав данных, цели, права субъекта, сроки, обработка в РФ без трансграничной передачи; `noindex`.
- Согласие только явное (чекбокс без pre-checked).
- Пароли/почты — только в `managers.local.php`, никогда в git.

## Как работает демо и что проверить

Демо = публикация папки `site/` на GitHub Pages (`*.github.io`).

Чек-лист проверки демо:

1. Открыть главную: все секции на месте, телефон `+7 (900) 000-00-00` в 4 местах index.html.
2. Ширина 320 и 375 px: нет горизонтального скролла, кнопки ≥52 px, текст ≥16 px.
3. Липкая нижняя панель «Позвонить / Оставить заявку» видна при скролле (моб.).
4. Маска телефона: ввод `89991234567` → `+7 (999) 123-45-67`.
5. Смена «способ связи» на Telegram/Max/VK/WhatsApp показывает поле ника; на «Перезвонить» — скрывает.
6. Отправка без чекбокса согласия → ошибка на русском, заявка не уходит.
7. Успешная отправка в demo → зелёное сообщение с меткой «демо-режим» и ссылкой на `zayavka.html`.
8. В футере видна ссылка «Пример письма менеджеру (демо)» и бейдж «Демо-режим».
9. `policy.html` открывается в новой вкладке, содержит текст 152-ФЗ.
10. **Демо НЕ принимает заявки** — предупредить заказчика: это витрина интерфейса.

Для проверки реальной отправки локально: `php -S 127.0.0.1:8080`, отправить форму, посмотреть `logs/submissions.log` (режим `test`).

## Запуск на реальном домене в России после покупки заказчиком

1. **Домен** — купить у российского регистратора (REG.RU, RU-CENTER, Names.ru и т.п.).
2. **Хостинг** — выбрать хостинг в РФ с поддержкой PHP 8.x (REG.RU, Beget, Timeweb, Sprinthost и аналоги). Данные заявок остаются в РФ — требование 152-ФЗ выполнено.
3. **Загрузка** — залить на хостинг содержимое `site/` в корень (public_html) **плюс** `send.php`, папки `config/` и `logs/` (этих файлов нет в `site/` — они нужны только на сервере). Альтернатива: залить весь корень проекта, но убрать служебные папки из веб-доступа.
4. **Конфиг** — задать `TO_EMAIL`, `FROM_EMAIL` через **env** (приоритет) или в `config/managers.local.php`; поставить `MAIL_MODE => 'test'`.
5. **Телефон и реквизиты** — заменить `+7 (900) 000-00-00` на реальный номер во всех 4 местах `index.html` (и в футере `policy.html`/`zayavka.html` при необходимости); в `policy.html` заполнить реквизиты оператора (ФИО, ИНН, ОГРНИП, адрес, e-mail) вместо плейсхолдеров.
6. **Проверка защиты** — открыть в браузере `/config/managers.local.php` и `/logs/submissions.log` — сервер должен отдавать **403** (`.htaccess` в папках + корневой `.htaccess`; на nginx — `deny all` для `/config/`, `/logs/`, `/tests/`, `/scripts/`).
7. **Тестовое письмо** — отправить заявку с сайта, убедиться, что в `test`-режиме запись появилась в логе; затем переключить `MAIL_MODE => 'real'` и отправить ещё одну — письмо должно прийти на `TO_EMAIL`.
8. **SPF/DKIM** — настроить на почтовом ящике `FROM_EMAIL` (справка регистратора/хостинга), иначе письма попадут в спам.
9. **Передача заказчику** — отдать доступы: хостинг, домен, почта менеджера, админка (если есть), этот README и `ACCEPTANCE_CHECKLIST.md`.

Иностранные хостинга как основные не используются.

## Тесты: что покрыто и что вручную

**Автотесты (`php tests/run_tests.php`, 26 проверок):** валидная заявка и режим test; согласие (нет / 0); honeypot (тихий ok, без лога); имя (пустое, >120); телефон (3 цифры / 10 цифр / 20 цифр); ник (короткий, кириллица, пустой, необязателен для «перезвонить»); неизвестный способ связи; rate-limit (5×200 → 6-й 429); GET → 405; пустое тело → 400.

**Синтаксис:** `node --check js/core.js js/script.js js/config.js`, `php -l send.php` и др.  
**JS unit:** `node --test tests/js_core.test.js` (маска, валидация, resetForm — без зависимостей).

**Ручная браузерная проверка:** маска телефона и условные поля в живом UI; адаптив 320 / 375 / 768 / 1024 / 1440; отсутствие горизонтального скролла; липкая панель; `prefers-reduced-motion`; фокус и клавиатурная навигация; видимость ссылки на политику в новой вкладке; тексты ошибок/успеха в форме.
